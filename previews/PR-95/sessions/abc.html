Approximate Bayesian Computation

Inference when you cannot write down a likelihood

Estimated time: 1-1.5 hours | Requires: Observation models

Lecture slides

Introduction

Yesterday ended on a question. If a negative log-likelihood is a distance function between prediction and data, and choosing Poisson over negative binomial is choosing between distances, then why not choose the distance directly?

That is what Approximate Bayesian Computation does. It drops the likelihood entirely, simulates from the model, and keeps the parameters whose simulations land close enough to the data under a distance you pick yourself. This matters well beyond convenience: for many models the likelihood cannot be written down at all, and a simulator is all you have.

Objectives

In this session you will:

  1. Implement ABC rejection sampling from scratch
  2. Find a workable acceptance threshold, and see why that is the hard part
  3. Implement ABC-SMC and compare it against rejection sampling
  4. Compare likelihood-based and distance-based posteriors on the same data
  5. Test how each approach responds to a single outlying observation

Simple SIR model for comparison

For this session, let’s use a simpler SIR model to make the concepts clearer:

"""
Simple SIR model for pedagogical purposes.
"""
function simulate_sir(θ, init_state, times)
    R_0, D_inf = θ[:R_0], θ[:D_inf]

    function sir_ode!(du, u, p, t)
        S, I, R = u
        β, γ = p
        N = S + I + R

        du[1] = -β * S * I / N
        du[2] = β * S * I / N - γ * I
        du[3] = γ * I
    end

    β = R_0 / D_inf
    γ = 1.0 / D_inf
    u0 = [init_state[:S], init_state[:I], init_state[:R]]
    prob = ODEProblem(sir_ode!, u0, (times[1], times[end]), [β, γ])
    sol = solve(prob, Tsit5(), saveat=times)

    # Extract incidence (new infections per day)
    S_values = sol[1, :]
    incidence = [0.0; -diff(S_values)]

    return DataFrame(time=times, S=S_values,
                     I=sol[2, :],
                     R=sol[3, :],
                     Inc=incidence)
end

Approximate Bayesian Computation

ABC: Making the distance explicit

Instead of choosing a parametric likelihood, ABC directly chooses:

  1. Summary statistics: What features of the data matter?
  2. Distance metric: How do we measure similarity?
  3. Threshold: How close is “close enough”?

Here is a simple ABC rejection sampler from scratch:

"""
Simple ABC rejection sampler.
Samples from prior, simulates data, accepts if distance < threshold.
"""
function abc_rejection(prior_sampler, simulator, distance_fn, observed_data,
                      threshold, n_samples)
    samples = []
    n_attempts = 0
    max_attempts = n_samples * 1000  # Give up after many attempts

    while length(samples) < n_samples && n_attempts < max_attempts
        n_attempts += 1

        # Sample from prior
        θ = prior_sampler()

        # Simulate data
        simulated_data = simulator(θ)

        # Compute distance
        d = distance_fn(simulated_data, observed_data)

        # Accept if close enough
        if d < threshold
            push!(samples, θ)
        end
    end

    acceptance_rate = length(samples) / n_attempts
    println("Acceptance rate: $(round(acceptance_rate * 100, digits=2))%")
    println("Attempts needed: $n_attempts")

    ## The attempt count is returned as well as printed, so the comparison at the
    ## end of the session can put it beside the ABC-SMC simulation count
    return samples, n_attempts
end

# Prior sampler
function sample_from_prior()
    R_0 = rand(Uniform(1.0, 20.0))
    D_inf = rand(Uniform(1.0, 10.0))

# Simulator
function simulate_sir_abc(params)
    R_0, D_inf, ρ = params
    θ = Dict(:R_0 => R_0, :D_inf => D_inf)
    traj = simulate_sir(θ, init_test, times)
    return ρ .* traj.Inc[2:end]  ## drop the padding zero at t = 0, to match the observations
end

# Distance functions
distance_L1(sim, obs) = sum(abs.(sim .- obs))

function distance_L2(sim, obs)
    return sqrt(sum((sim .- obs).^2))
end

function distance_weighted(sim, obs)
    # Weight by 1/observation (similar to Poisson variance structure)
    weights = 1.0 ./ (obs .+ 1.0)
    return sum(weights .* abs.(sim .- obs))
end

NoteUnderstanding the distance functions

We’ve defined three distance functions, each with different properties:

  • L1 (Manhattan): sum(|sim - obs|) - Sums absolute deviations. Robust to outliers because large errors contribute linearly. A mismatch of 20 cases counts twice as much as a mismatch of 10.

  • L2 (Euclidean): sqrt(sum((sim - obs)²)) - Root of squared deviations. Penalises large errors more heavily than L1. A mismatch of 20 cases counts four times as much as 10 (because 20² = 400 vs 10² = 100).

  • Weighted: sum(w × |sim - obs|) where w = 1/(obs + 1) - Weights inversely by observation size. This mimics Poisson variance scaling: a mismatch of 5 when obs=2 is penalised more than when obs=50. Useful when you care about relative rather than absolute fit.

When to use each:

  • L1: Good default. Robust to occasional large mismatches.
  • L2: When large deviations are particularly bad (e.g., outbreak peaks).
  • Weighted: When fit quality should be scale-independent (similar to Poisson likelihood).

TipChoosing the threshold

ABC rejection sampling is sensitive to the threshold choice:

  • Too strict (e.g., 100): below the closest this model can get, so it accepts nothing at all and exhausts the attempt budget
  • Too loose (e.g., 1000): Fast, but approximate posterior is close to the prior
  • In between (e.g., 200-400): Runs quickly, but at the loose end of this band the posterior still carries a good deal of the prior

We start with a relaxed threshold (300) here. Note what that costs: the run below accepts around a quarter of what it proposes, which by the guidance later in this session is loose enough that the posterior is still carrying a good deal of the prior. The exercise that follows asks you to tighten it.

If you get 0 samples: Increase the threshold (try 400, then 500). The sampler may be struggling to find parameter combinations that produce simulations close to the data. This can happen due to random variation - ABC is inherently stochastic.

# Start with a relaxed threshold to get some samples

TipExercise: Find a workable threshold

The threshold above (300) was chosen for you. Find out what it is doing by changing it.

  1. Re-run the sampler with a stricter threshold, say 200. How many simulations does it get through, and how long does it take?
  2. Re-run with a loose one, say 800. How wide is the resulting posterior for \(R_0\) compared with the run at 300?
  3. What is the trade-off you are making, and how would you decide on a value if you had no answer to compare against?
TipSolution

Tightening the threshold narrows the posterior but the acceptance rate collapses, so you wait much longer for the same number of samples: at 200 about 2% of prior draws are accepted against about a quarter at 300, so the same 200 samples cost roughly ten times as many simulations. There is a floor as well. The closest this SIR gets to these data anywhere in the prior box is a distance of about 165, so a threshold below that accepts nothing however long you leave it running.

Loosening it accepts almost everything, so the sampler is fast but the posterior drifts back towards the prior: you are no longer conditioning on the data very much.

There is no way to pick \(\epsilon\) from first principles. In practice you lower it until either the posterior stops changing or the acceptance rate becomes unaffordable, whichever comes first. This is exactly the weakness that ABC-SMC in the next section is designed to address, by walking the threshold down automatically.

Compare distance metrics

Different distance functions give different results.

TipExercise: Predict before you run

Before running the cell below, write down your answer to this: if one day’s count were much higher than the model predicts, which of the three distances — L1, L2 or the weighted distance — would react most strongly, and why?

Then run it and see whether the ordering matches what you expected.

TipSolution

L2 reacts most strongly, provided the rest of the trajectory fits. It squares the deviation, so a single day off by 30 contributes 900 while thirty days off by 1 contribute 30 between them. Squared distances are dominated by their worst point.

L1 adds the absolute deviations, so that same bad day contributes 30 and nothing more. It is the forgiving choice, and it is why L1 is a common default in ABC when you expect reporting glitches.

The caveat matters here more than usual, as the cell below shows. Our SIR model fits these data badly, and against a badly fitting simulation the L2 total is already dominated by the model’s systematic errors, so the injected outlier accounts for a smaller share of L2 than of L1. The rule of thumb describes a model that is otherwise doing well.

The weighted distance depends entirely on the weights. If it upweights the peak and the outlier falls near the peak, it can react more sharply than either; if the outlier falls somewhere it downweights, it can barely notice.

The connection worth carrying forward is that this is the same comparison as Poisson against negative binomial, which you met yesterday. A Poisson likelihood behaves like L2 in that one improbable day dominates the total; a negative binomial behaves more like L1. Choosing a distance and choosing an observation model are the same decision about how much a single surprising observation should count.

The three distances are on different scales, so their raw values say nothing about sensitivity. Watch instead how much each one moves when a single day goes wrong.

# Take one simulation, disturb a single day of the data it is compared against,
# and ask how much of each distance that one day is then responsible for
test_params = [10.0, 2.5, 0.8]
test_sim = simulate_sir_abc(test_params)

spiked = copy(observed_data)
spiked[30] += 30  # one day, thirty extra cases

# Per-day contributions to each distance, before summing
l1_terms(sim, obs) = abs.(sim .- obs)
l2_terms(sim, obs) = (sim .- obs) .^ 2
weighted_terms(sim, obs) = abs.(sim .- obs) ./ (obs .+ 1.0)

# The likelihood fit's posterior mean, taken from the chain rather than copied out
# of it. It is closer than the simulation above but still a poor fit, at a distance
# of about 308, which the threshold of 300 would reject
fitted_params = [mean(chain_poisson[:R_0]), mean(chain_poisson[:D_inf]),
                 mean(chain_poisson[:ρ])]
fitted_sim = simulate_sir_abc(fitted_params)

for (label, sim) in (("poorly fitting simulation", test_sim),
                     ("closer simulation", fitted_sim))
    println(label)
    for (name, terms) in (("L1", l1_terms), ("L2", l2_terms),
                          ("weighted", weighted_terms))
        t = terms(sim, spiked)
        println("  ", rpad(name, 9), " day 30 contributes ",
                round(100 * t[30] / sum(t), digits=1), "% of the summed terms")
    end
    ## And what the spike does to the distances the session actually uses, which
    ## take a root in the L2 case
    for (name, d) in (("L1", distance_L1), ("L2", distance_L2),
                      ("weighted", distance_weighted))
        before, after = d(sim, observed_data), d(sim, spiked)
        println("  ", rpad(name, 9), " distance moves ",
                round(100 * (after - before) / before, digits=1), "%")
    end
end

The ordering depends on how well the rest of the trajectory fits, which is worth more than the headline rule. Against the closer simulation, the spiked day accounts for about a fifth of the summed squares and about a tenth of the summed absolute errors, so squaring does concentrate attention on it. Look at the second block, though. distance_L2 takes the square root of those summed squares, and once it does the two distances move by almost the same amount. That is not the root cancelling the squaring in general. It happens because neither simulation here is close to the data: the spike is small against a sum of squares the model’s own errors already dominate, so the root linearises the change. Give the same spike to a trajectory that does fit and the textbook behaviour comes back. The best fit available anywhere in the prior box moves L1 by 18% and L2 by 48%, and a near-perfect series moves them by 38% and 161%. Against the poorly fitting one the ordering reverses, because L2 is already saturated by the model’s own errors and one more large deviation barely registers among them.

An outlier is only conspicuous relative to how well everything else is explained.

Notice that choosing a distance metric in ABC is philosophically similar to choosing a parametric likelihood.

ABC-SMC: Sequential Monte Carlo ABC

The rejection sampler above is inefficient - most samples from the prior are rejected, wasting computation. ABC-SMC (Sequential Monte Carlo ABC) attacks that by gradually tightening the acceptance threshold across multiple generations, reusing the particles that survived the previous one.

The key idea, introduced by Toni et al. (2009), is:

  1. Start permissive: Begin with a loose threshold that accepts many samples
  2. Gradually tighten: Reduce the threshold across generations
  3. Reuse good samples: Instead of sampling from the prior each time, perturb samples that passed the previous threshold

The aim is to reach a threshold that rejection sampling could not afford, by refining particles that are already close rather than searching blindly from the prior each time. How much that saves depends entirely on the problem, the schedule and the kernel, so treat quoted speedup factors with suspicion until you have counted your own.

NoteImplementation: ABC-SMC

This is a simplified ABC-SMC for pedagogical purposes. It does compute the importance weights, which is what makes the sample valid, but production implementations (like ApproxBayes.jl or GpABC.jl) add adaptive thresholds and better perturbation kernels.

The redraw is worth a closer look. A perturbation landing outside the prior sends the loop back to its start, which draws a new parent as well as a new perturbation, so the proposal is the whole mixture restricted to the prior box. The constant that restriction introduces is the same for every particle, so it cancels when the weights are normalised, and the weights computed here are exact. Had the redraw kept the same parent and only re-perturbed, it would not cancel, and children of near-boundary particles would come out over-weighted.

Note on Threads.@threads: The code below uses Threads.@threads to parallelise the particle loop — this macro distributes iterations across available CPU threads, so each particle can be simulated concurrently. For this to have any effect, Julia must be started with multiple threads (e.g., julia -t auto). See the threading note in MCMC Diagnostics for setup instructions. Without multiple threads, the loop runs sequentially (slower but still correct).

# The prior appears twice: as bounds to sample from, and as a support check used
# when weighting. The importance weights below are a ratio of prior density to
# perturbation density, and because all three priors are uniform that numerator
# is a constant which cancels in the normalisation, so only the support matters.
const PRIOR_BOUNDS = [(1.0, 20.0), (1.0, 10.0), (0.1, 1.0)]

in_prior(θ) = all(lo <= θ[i] <= hi for (i, (lo, hi)) in enumerate(PRIOR_BOUNDS))

"Standard deviation of the perturbation kernel applied to a particle."
kernel_sd(θ) = 0.1 .* abs.(θ)

"Density of the perturbation kernel that moves `θ_from` to `θ_to`."
function kernel_pdf(θ_to, θ_from)
    sds = kernel_sd(θ_from)
    return prod(pdf(Normal(θ_from[d], sds[d]), θ_to[d]) for d in eachindex(θ_to))
end

"""
Simple ABC-SMC implementation.
Uses a sequence of decreasing thresholds, perturbing the particles that survived
the previous one. Returns the particles, their importance weights, the number of
simulations each generation cost, and the effective sample size of each
generation's weights.
"""
function abc_smc(prior_sampler, in_prior, simulator, distance_fn, observed_data,
                thresholds, n_particles; max_simulations_per_generation = 100_000)

    particles = Vector{Vector{Float64}}()
    weights = Float64[]
    sim_counts = Int[]
    ess_history = Float64[]

    for (t_idx, threshold) in enumerate(thresholds)
        println("\nGeneration $t_idx: threshold = $threshold")
        new_particles = Vector{Vector{Float64}}(undef, n_particles)
        simulations = Threads.Atomic{Int}(0)

        Threads.@threads for i in 1:n_particles
            while simulations[] < max_simulations_per_generation
                θ = if t_idx == 1
                    prior_sampler()
                else
                    # Draw a survivor in proportion to its weight, then perturb it
                    θ_old = particles[sample(1:length(particles), Weights(weights))]
                    θ_old .+ randn(length(θ_old)) .* kernel_sd(θ_old)
                end

                # A perturbation can leave the prior's support; redraw rather than
                # simulate, and do not count it as a simulation
                in_prior(θ) || continue

                Threads.atomic_add!(simulations, 1)
                if distance_fn(simulator(θ), observed_data) < threshold
                    new_particles[i] = θ
                    break
                end
            end
        end

        if !all(i -> isassigned(new_particles, i), 1:n_particles)
            error("gave up at threshold $threshold after $(simulations[]) " *
                  "simulations; loosen the schedule or raise the budget")
        end

        # Importance weights. A particle reached this generation through the
        # perturbation kernel rather than from the prior, and the weights undo
        # that: numerator is the prior density, denominator is how likely the
        # previous generation was to propose it. The numerator is written as 1.0
        # because these priors are uniform, so the density is the same constant
        # for every particle and divides out when the weights are normalised.
        # With a non-uniform prior it would have to be evaluated. Skipping the
        # weights altogether leaves the sample biased towards wherever the
        # kernel happens to concentrate.
        new_weights = if t_idx == 1
            fill(1.0 / n_particles, n_particles)
        else
            w = [1.0 / sum(weights[j] * kernel_pdf(new_particles[i], particles[j])
                           for j in eachindex(particles))
                 for i in 1:n_particles]
            w ./ sum(w)
        end

        particles = collect(new_particles)
        weights = new_weights
        push!(sim_counts, simulations[])
        push!(ess_history, 1 / sum(abs2, weights))

        weighted_R_0 = sum(weights[i] * particles[i][1] for i in eachindex(particles))
        println("  Simulations: $(simulations[]),  weighted mean R_0: ",
                round(weighted_R_0, digits=2),
                ",  ESS: ", round(ess_history[end], digits=1), " of $n_particles")
    end

    return particles, weights, sim_counts, ess_history
end

Compare the printed counts rather than taking any efficiency claim on trust, including this session’s.

The generations usually get more expensive, not less: the first is cheap because a loose threshold accepts almost anything, and each tightening tends to cost more simulations per particle than the last. Now and then a later generation comes out cheaper, so read the direction rather than the individual numbers.

Whether the total beats rejection sampling depends on the schedule, and on a problem this small it does not. The two totals printed above are not comparable as they stand, though: the rejection run stops at a threshold of 300 and ABC-SMC goes on to 250, so one has bought a tighter posterior than the other. Compare them at the same final threshold, and per effective sample rather than per draw. Rejection sampling’s draws are unweighted, so its effective sample size is the number of draws; run to 250 it needs about 2300 simulations for 200 of them, which is about 11 each. ABC-SMC’s 100 particles are weighted, so the figure to divide by is the effective sample size printed for its final generation, which is well below 100. Its whole total counts, because the earlier generations cannot be skipped: 831 simulations against a final effective sample size of 18.5 is about 45 each. So rejection is roughly four times cheaper on this run. That gap is not stable, though. The effective sample size of the last generation swings widely between runs, and across repeated runs the median comes out nearer 20 per effective sample, which puts rejection about twice ahead rather than four times. A generation whose effective sample size collapses tends to make the next one dearer, because the next generation perturbs from whatever few particles still carry weight. Prior acceptance is about a quarter at a threshold of 300 and still around 9% at 250, so rejection can reach the tighter threshold directly. ABC-SMC concentrates its effort where the data are, without being told where that is, and that pays on problems whose prior acceptance is orders of magnitude lower than this one.

Watch the effective sample size as well. The first generation has all 100 particles, because they are drawn from the prior and weighted equally. After that it drops sharply, often to a small fraction of the particle count, and how far varies a great deal between runs: repeat this with different seeds and generation 2 can land anywhere from single figures to about half the particles. What does not vary is the direction.

That is weight degeneracy. The effective sample size printed for the final generation, against the 100 particles it is computed from, is the measure of it, and the density plot above is drawn from correspondingly fewer distinct parameter vectors than its 1000 draws suggest, and its apparent concentration is partly an artefact of duplication rather than evidence of a sharper posterior. Production implementations resample between generations and adapt the kernel width to control this; ours does neither, so read the final spread as indicative rather than as a posterior you would report.

ImportantAssessing ABC posterior quality

Rejection ABC does not produce chains, so chain diagnostics like R-hat have nothing to work with. ABC-SMC does carry weights, and the effective sample size of those weights is worth watching, as above. Beyond that, assess ABC posterior quality by:

  • Acceptance rate: Very low rates (< 0.1%) suggest the threshold is too strict or the model is a poor fit. Very high rates (> 10%) suggest the threshold is too loose and the posterior is close to the prior.
  • Visual comparison with likelihood-based posteriors: When a likelihood is available (as in this session), run both methods and compare. Large discrepancies suggest either the ABC threshold is too loose or the distance metric captures different features than the likelihood.
  • Threshold sensitivity: Run ABC with several thresholds. If the posterior changes substantially as you tighten the threshold, it has not yet converged — you need a stricter threshold (and more computation).
  • Coverage of prior: If the ABC posterior looks very similar to the prior, the threshold is too loose and the data are not informing the inference.
  • Replicate runs: Run ABC multiple times with different random seeds. If posteriors differ substantially between runs, you need more particles or a less strict threshold.

The big picture: Likelihood vs ABC

Now let’s step back and compare all our approaches - parametric likelihoods and ABC methods - to see what’s fundamentally different (and what’s surprisingly similar).

When does it matter?

Sensitivity analysis

The choice between Poisson, NegBin, and ABC matters most when:

  1. Outliers: Extreme observations far from predictions
  2. Tail behaviour: Rare events (very low or very high counts)
  3. Overdispersion: Systematic variance > mean in data
  4. Model misspecification: When the mechanistic model is wrong

We can test sensitivity to outliers:

# Helper function to simulate and return incidence
function simulate_and_summarize(params)
    R_0, D_inf, ρ = params
    θ = Dict(:R_0 => R_0, :D_inf => D_inf)
    traj = simulate_sir(θ, init_test, times)
    return ρ .* traj.Inc[2:end]  ## drop the padding zero at t = 0, to match the observations
end

# Create one synthetic dataset, then a copy of it with a single day disturbed.
# Drawing fresh noise for each would make the two datasets differ everywhere, and
# the comparison below would measure the noise rather than the outlier.
function synthetic_data()

    true_data = simulate_and_summarize(true_params)
    noisy_data = true_data .+ randn(length(true_data)) .* 2.0

end

Compare how the Poisson likelihood and ABC with L1 distance respond to the outlier.

Simulate from a few parameter sets, compute the Poisson log-likelihood and the L1 distance against both data_clean and data_outlier, and see which metric shifts more. If you have time, try a full fit with both and compare the posteriors.

TipHint: Outlier robustness

Poisson likelihood is sensitive to outliers because the log-probability drops sharply for counts far from the mean. An outlier of +30 cases when the model predicts 5 contributes a large penalty to the log-likelihood, pulling parameter estimates towards values that accommodate the outlier.

ABC with L1 distance (defined earlier as sum(abs.(sim .- obs))) is more robust because the penalty grows linearly with the discrepancy, not exponentially. A single outlier affects the total distance, but doesn’t dominate as severely.

For likelihood-based inference, the Negative Binomial distribution (covered earlier in this session) offers a middle ground: its heavier tails make it less sensitive to occasional large deviations than Poisson, while still providing a proper likelihood for MCMC.

# Poisson log-likelihood
function poisson_loglik(predicted, observed)
    ll = 0.0
    for i in eachindex(observed)
        λ = max(predicted[i], 1e-10)
        ll += logpdf(Poisson(λ), round(Int, observed[i]))
    end
    return ll
end

The philosophical question

Is there a “correct” observation model?

No! There are only:

  1. More or less mechanistically motivated choices
    • E.g., modelling test sensitivity explicitly vs using NegBin
  2. More or less flexible choices
    • Poisson (rigid) → NegBin (flexible) → ABC (very flexible)
  3. More or less computationally convenient choices
    • MCMC with parametric likelihood (fast)
    • ABC (slow but general)

Practical advice

When to use parametric likelihoods (Poisson/NegBin):

  • You have a tractable likelihood function
  • You want efficient inference (MCMC with gradients)
  • The parametric family is flexible enough
  • You’re comfortable with the implicit distance metric

When to use ABC/likelihood-free:

  • Likelihood is truly intractable (stochastic models, agent-based models)
  • You want to make your distance metric explicit
  • You care more about specific summary statistics than full data
  • You want robustness to model misspecification

Best practice:

  • Try multiple observation models (Poisson, NegBin, ABC with different distances)
  • Check if scientific conclusions change
  • If they don’t → observation model choice doesn’t matter much
  • If they do → you’ve learned something about what features of the data drive inference!

Learning points

TipLearning points
  • ABC replaces the likelihood with an explicit distance, but choosing L1 over L2 over a weighted distance is the same kind of choice as picking Poisson over negative binomial
  • The acceptance threshold is the hard part: too tight and nothing is accepted, too loose and you are sampling the prior
  • ABC-SMC walks the threshold down in stages, concentrating effort where the data are without being told where that is, at the cost of weights that can become very uneven. On a problem as small as this one, where the prior already accepts often, it does not pay for itself
  • Likelihoods are fast and need a tractable model; ABC is slow and needs only a simulator
  • A single outlying observation moves a Poisson likelihood far more than an L1 distance, which is the clearest sign the two are different distance functions

Going further

Summary statistics for ABC

Instead of comparing full time series, ABC often works better with carefully chosen summary statistics. For epidemic data, useful summaries include:

  • Total cases: Sum of all observations
  • Peak timing: Day with maximum incidence
  • Peak height: Maximum daily incidence
  • Growth rate: Initial doubling time or exponential growth rate
  • Final size: Cumulative attack rate

Here is an example of how to define and use summary statistics for ABC:

"""Extract summary statistics from an epidemic time series."""
function epidemic_summaries(data)
    return [
        sum(data),                          # Total cases
        argmax(data),                       # Peak timing (day index)
        maximum(data),                      # Peak height
        sum(data[1:min(5, length(data))])   # Early cumulative cases (proxy for growth rate)
    ]
end

# Distance on summaries rather than full time series
function distance_summaries(sim, obs)
    s_sim = epidemic_summaries(sim)
    s_obs = epidemic_summaries(obs)
    # Normalise each summary by the observed value to make them comparable
    return sum(abs.(s_sim .- s_obs) ./ (abs.(s_obs) .+ 1.0))
end

Using fewer, well-chosen summaries can make ABC more robust to noise and model misspecification. However, there is a trade-off: summaries that discard too much information will produce wider posteriors. The choice of which summaries to use is problem-specific and often requires experimentation.

Try passing distance_summaries to abc_rejection in place of distance_L1 and compare the posteriors you get. The four summaries throw away the day-to-day shape of the curve, so expect them to widen. How much each parameter widens tells you how much of what identified it was in the detail of the trajectory rather than in its peak, total and timing.

Alternative observation models

The choice of observation model affects inference more than many researchers realise. Consider exploring:

  • Gaussian likelihood: Appropriate when counts are large and approximately symmetric
  • Zero-inflated models: When surveillance systems miss entire days
  • Reporting delay models: When cases are reported with variable lag

Computing the variance/mean ratio in your data can help diagnose whether Poisson (ratio ≈ 1) or Negative Binomial (ratio > 1) is more appropriate.

Robust distance metrics

For ABC with outliers or model misspecification, consider robust distances:

  • Median absolute deviation instead of mean squared error
  • Quantile-based distances that down-weight extreme values
  • Feature-based distances that focus on epidemiologically meaningful patterns

Try replacing distance_L1 in abc_rejection with a median-based version, distance_median(sim, obs) = median(abs.(sim .- obs)), and compare the posteriors. A robust distance stops a handful of large daily discrepancies dominating the fit, so how much the posterior moves tells you how much of it was being decided by a few days.
